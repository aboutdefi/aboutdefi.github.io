RPC URLs in EVM network directories: who reviews them

Maintainers review RPC submissions before listing them; providers run the endpoints. Learn what Chainlist checks and what your wallet confirms.

The Blocktape Editors Nov 26, 2026 · 01:36 UTC2 min read 78ecc0

Maintainers review pull requests before an RPC URL is listed; the provider behind it runs the endpoint. That distinction tells you what trust you extend when adding a network.

Chainlist builds network data on the open ethereum-lists/chains registry, which chainid.network also uses. Chainlist presents network details and RPC endpoints drawn from that data and its own public repository.

How an RPC URL gets listed

Anyone can propose an endpoint through a pull request to DefiLlama’s public chainlist GitHub repository. The project’s instructions direct contributors to add RPCs to the relevant chain in extraRpcs.js.

Maintainers review the proposed change before merging it, including its format and basic validity. The pull request and review history show the change being considered; being merged means it was accepted into the directory, not that the endpoint has passed an ongoing security or reliability audit.

The file’s commit history makes that process checkable. Find an endpoint in extraRpcs.js, open its GitHub history, and trace the commit to the pull request that added it. You can see who proposed the change and when it entered the file, then read the discussion for the context maintainers had at the time.

What the listing tells you about the provider

Once listed, an RPC endpoint is run by its provider, which controls its uptime, logging and the data it serves. Directory labels reflect the provider’s stated policy when the endpoint was submitted; they are not a live check of how it is operated now.

Say you add Polygon from Chainlist in MetaMask. The URL shown in the wallet prompt points to an RPC provider, and requests sent through it expose your IP address and activity to that provider. Its responses supply the blockchain data your wallet displays.

MetaMask can check the endpoint’s chain ID using the JSON-RPC method eth_chainId, which returns the ID used for replay-protected transactions, as documented by ethereum.org. That confirms which chain the endpoint reports; it does not tell you who operates it or what they log.

Before accepting the Polygon URL, identify its provider and decide whether you trust that provider with your requests. The pull request history can show how the URL entered the directory; your choice of endpoint determines who receives your wallet’s RPC traffic.
