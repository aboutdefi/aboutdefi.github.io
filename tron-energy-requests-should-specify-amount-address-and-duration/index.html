TRON Energy requests should specify amount, address and duration

A useful request names the receiving address, Energy target, timing and lock terms; TRON delegation assigns resources, while the staked TRX stays with its owner.

The Blocktape Editors Oct 22, 2026 · 17:26 UTC3 min read 1962d3

A TRON Energy delegation request should state the receiving address, the amount needed, when it is needed and how long it should remain available. TRON’s Stake 2.0 system lets an account delegate Energy generated by staked TRX; the staked TRX remains with the delegator.

What details should a delegation request include?

Give the provider the address that will use the Energy and a specific resource target, then state the time window and requested duration. Include whether the address can receive delegated resources: TRON’s documentation says delegation cannot be made to a contract address.

Explain the transaction or activity the Energy will cover, such as a planned smart-contract call, so the provider can assess the target. For a guide to using Tron Energy from your own wallet, see the separate wallet walkthrough. That detail can help you decide whether to request a delegation or use resources already available to your account.

  • Receiving TRON address
  • Energy amount and the transaction it is meant to cover
  • Start time and required duration
  • Any lock period or release terms agreed with the provider

How is delegated Energy measured?

TRON’s delegation transaction records a balance in sun, the smallest TRX unit, rather than a fixed number of Energy units. The balance represents the staked TRX value behind the resource allocation; the Energy that value produces depends on the network’s overall resource distribution.

That distinction matters when comparing offers: ask whether a quoted figure means Energy units or the TRX stake value used to produce them. TRON provides a query for the maximum amount an account can delegate, and its documentation notes that recent resource use can reduce that available amount.

What should you agree before the delegation?

Confirm whether the delegation is locked and when it can be reclaimed. TRON says an unlocked delegation can be canceled by its owner at any time, while a locked delegation stays with the recipient for the agreed period; lock periods are measured in blocks, not seconds.

Check the receiving address character by character and agree how both sides will verify that the resources arrived. A request is only a negotiation: the delegator must submit and sign the on-chain transaction, and the recipient should check the resulting resource balance before relying on it.

For most one-off needs, request only the Energy and duration needed for the planned activity, with an unlocked delegation if the provider agrees. Once the transaction is confirmed, check the account’s resources before sending the contract call.
