Why Your Crypto Swap Is Still Pending

A swap can remain pending because its source transaction is unconfirmed, its route is waiting on another network, or the provider has not settled the trade yet.

The Blocktape Editors Sep 29, 20262 min read d6171c

A crypto swap can stay pending because the transaction has not been confirmed, the route is waiting for another network, or the service has not finished settling the trade. The status depends on where the swap is happening: in a wallet or decentralized exchange, through a centralized service, or across a bridge.

What does a pending swap status mean?

A pending label means the service has not recorded the swap as complete; it does not, by itself, show whether funds are lost. Check the wallet or provider’s transaction details to see whether the source transaction was submitted, confirmed, or rejected, and whether a second transaction is still required.

For an on-chain swap, the source transaction must be included in a block before the exchange can execute. A transaction explorer can show whether it is still waiting, has failed, or has been confirmed; the wallet’s display may update later than the network record.

Why is the transaction taking so long?

A transaction can wait when the network is busy or its fee is too low for validators to include it promptly. The wallet’s fee estimate and the network’s current conditions affect how quickly it moves; raising a fee may help only if the wallet and network support replacing the pending transaction.

Some swaps also require more than one network step. Bridge routes, for example, can depend on the destination asset and the trust model used to move value between networks; this account of XMR bridge routes and destination assets explains why those details matter. A source-side confirmation does not necessarily mean the destination-side transfer has finished.

Can the swap fail after it starts?

Yes. A decentralized exchange may reject a trade if its price moves beyond the slippage limit set by the user, or if the transaction runs out of gas before it completes. A centralized service may show a pending status while it checks a deposit or processes an order; its own status page is the source for those steps.

Before retrying, check the transaction hash in the relevant network explorer and compare it with the provider’s status. This helps distinguish a delayed transaction from one that failed or completed while the app still shows an old status.

  • Still unconfirmed: Wait or use the wallet’s supported fee replacement option.
  • Confirmed on the source network: Check the swap service or bridge for the next step.
  • Failed or reverted: Read the transaction result before submitting another swap.
  • No transaction hash: Ask the provider whether the order was received; do not assume it reached the network.

What should you do while it is pending?

Do not submit the same swap again until you know what happened to the first one. A second attempt can create another trade or transfer if the original later completes. Never share a recovery phrase or private key with someone claiming they can speed up or release a pending swap.

For a network transaction, use the wallet’s documented controls and the transaction explorer; for a service-managed trade, contact that provider with the order reference. The next useful signal is a confirmed, failed, or provider-updated status, which shows whether to wait, troubleshoot, or start a new transaction.
